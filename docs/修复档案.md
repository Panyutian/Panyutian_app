### #01 MQTT命令重复执行 → 扫描APP失败

**版本**：v22（之前所有版本）
**现象**：扫描APP时报HTTP 500，包管理器返回 `Failure retrieving array; only received 63 of 333`

**根因**：
- `startStateWatchdog` 每次断线重连都注册新的 MQTT 回调
- 旧回调不清理，累积到30+个
- 同一条 MQTT 命令被重复执行几十次
- 30+ 线程并发调用 `PackageManager.getInstalledApplications`
- Binder缓冲爆满 → 返回不完整结果

**修复**：
```kotlin
// MqttBridge.kt
private val processedReqIds = Collections.synchronizedMap(LinkedHashMap<String, Long>())
private val REQ_ID_TTL_MS = 5 * 60_000L

// handleIncomingCmd 开头加幂等去重
val reqId = payload.optString("req_id")
if (reqId.isNotEmpty()) {
    val now = System.currentTimeMillis()
    synchronized(processedReqIds) {
        processedReqIds.entries.removeAll { now - it.value > REQ_ID_TTL_MS }
    }
    if (processedReqIds.containsKey(reqId)) {
        Log.w(TAG, "⏭️ 重复命令已忽略: cmd=$cmd reqId=$reqId")
        return
    }
    processedReqIds[reqId] = now
}
```

**教训**：MQTT 重连必须清理旧订阅回调！

### #02 家长端推送更新 → 孩子端无弹窗

**版本**：v22（之前所有版本）
**现象**：家长端点"推送孩子端更新"，孩子端下载完APK但不弹安装界面

**根因**：
- Android 10+ 限制后台服务拉起 Activity
- `Intent.ACTION_VIEW` + `REQUEST_INSTALL_PACKAGES` 需要系统界面
- 后台服务无法启动安装器 Activity → 静默失败
- 即使拉起了，还要用户点"允许安装未知来源" → 体验差

**修复**：利用 DeviceOwner 权限的 `PackageInstaller.Session` API
```kotlin
private fun silentInstallViaPackageInstaller(apkFile: File): Boolean {
    if (!AdminReceiver.isDeviceOwner(this)) return false
    val installer = packageManager.packageInstaller
    val params = PackageInstaller.SessionParams(MODE_FULL_INSTALL)
    val sessionId = installer.createSession(params)
    installer.openSession(sessionId).use { session ->
        apkFile.inputStream().use { input ->
            session.openWrite("child_update", 0, apkFile.length()).use { out ->
                input.copyTo(out); session.fsync(out)
            }
        }
    }
    val pending = PendingIntent.getBroadcast(this, 0,
        Intent(this, SilentUpdateReceiver::class.java),
        PendingIntent.FLAG_UPDATE_CURRENT or PendingIntent.FLAG_IMMUTABLE)
    session.commit(pending.intentSender)  // ← 系统自动安装，无弹窗
    return true
}
```

**教训**：DeviceOwner 有特权！不要用普通安装方式，直接走 Session API 静默安装。

### #03 孩子端版本检查只查3条线路 → 跳过更新

**版本**：v23
**现象**：version.json 已更新，但孩子端判断"已是最新"不安装

**根因**：
- jsDelivr CDN 缓存不一致（实测17/18/19并存）
- 之前只查 3 条顺序线路
- 顺序尝试第一条成功即采用 → 容易被旧缓存压住
- 无 `Cache-Control: no-cache` 头 → CDN 强制缓存

**修复**：7条线路**并发**查询 + 禁缓存 + 取最高 versionCode
```kotlin
val urls = listOf(
    "https://cdn.jsdelivr.net/gh/Panyutian/Panyutian_app@main/version.json",
    "https://fastly.jsdelivr.net/gh/...",
    "https://gcore.jsdelivr.net/gh/...",
    "https://zzko.jsdelivr.net/gh/...",
    "https://ghfast.top/https://raw.githubusercontent.com/Panyutian/Panyutian_app/main/version.json",
    "https://gh-proxy.com/https://raw.githubusercontent.com/Panyutian/Panyutian_app/main/version.json",
    "https://raw.githubusercontent.com/Panyutian/Panyutian_app/main/version.json"
)
// 并发请求，取最高 versionCode
```
关键：HTTP 请求必须加 `Cache-Control: no-cache` 头！

**教训**：公共CDN边缘节点缓存不同步。不要顺序尝试，**并发取最高**才是王道。

### #04-07 BiometricPrompt 配置冲突 → 4次闪退

**版本**：v26→v28（连续3次修复才找到根因）

**现象**：家长端启动即闪退，`FATAL EXCEPTION`

**根因（4个，连续叠加）**：

#### #04 DeviceOwnerCredential + negativeButtonText 冲突
```kotlin
// ❌ 崩溃！两者功能重复
val canAuthenticate = biometricManager.canAuthenticate(
    BIOMETRIC_STRONG or BIOMETRIC_WEAK or DEVICE_CREDENTIAL
)
val promptInfo = BiometricPrompt.PromptInfo.Builder()
    .setNegativeButtonText("使用密码")  // 和 DEVICE_CREDENTIAL 冲突
    .build()
```
> BiometricPrompt 不允许同时设置 negativeButtonText 和支持 DEVICE_CREDENTIAL

**修复**：去掉 `DEVICE_CREDENTIAL`，我们自己有密码对话框。

#### #05 同上（修复不完整）
v27 只改了 canAuthenticate 但 PromptInfo 里可能残留其他问题。

#### #06 缺少 USE_BIOMETRIC 权限
Android 11（API 30）+ 必须声明此权限，否则 BiometricPrompt 直接抛异常。

**修复**：
```xml
<uses-permission android:name="android.permission.USE_BIOMETRIC" />
<uses-permission android:name="android.permission.USE_FINGERPRINT" />
```

#### #07 同上（修复不完整）

**教训**：BiometricPrompt 有**三重要求**：
1. ✅ Manifest 声明 USE_BIOMETRIC 权限
2. ✅ canAuthenticate 配置正确（不要加 DEVICE_CREDENTIAL 除非不用 negativeButtonText）
3. ✅ PromptInfo 配置正确（二选一：negativeButtonText 或 DEVICE_CREDENTIAL）

### #08 布局XML缺 layout_width → InflateException

**版本**：v28→v29
**现象**：家长端启动闪退，日志：
```
android.view.InflateException: Binary XML file line #508
You must supply a layout_width attribute.
```

**根因**：锁页 lock_overlay 里我写的3个 TextView 都**忘了写 layout_width 和 layout_height**：
```xml
<TextView
    android:text="🛡️"
    android:textSize="64sp"
    android:layout_marginBottom="16dp" />  <!-- ❌ 缺少宽高！ -->
```

**修复**：
```xml
<TextView
    android:layout_width="wrap_content"
    android:layout_height="wrap_content"
    android:text="🛡️"
    android:textSize="64sp" />
```

**教训**：Android XML 里**所有 View 都必须有 layout_width 和 layout_height**！写代码时不要用省略号偷懒。

### #09 无生物识别时认证流程卡死

**版本**：v30（修复前v26-v29都有此问题）
**现象**：设备无指纹/人脸 → 锁页只显示按钮 → 用户必须手动点 → 体验差

**根因**：setupAuthLock() 只处理了"有生物识别"的情况，没处理"无生物识别+有密码"和"都没有"的情况。

**修复**：三场景自动路由
```kotlin
val hasBio = canAuthenticate == BIOMETRIC_SUCCESS
val hasPwd = (prefs.getString("pwd", "") ?: "").isNotEmpty()
if (hasBio) {
    // 自动弹生物识别
} else if (hasPwd) {
    // 自动弹密码框
} else {
    // 首次使用，自动进入
    unlockApp()
}
```

**教训**：不要假设设备一定有生物识别，**必须覆盖所有场景**。

### #10 版本号双文件维护 → 易忘改

**现象**：每次升级要改 parent/build.gradle + child/build.gradle + version.json 共3处，容易漏。

**修复**：项目级 build.gradle 用 JsonSlurper 读 version.json
```groovy
import groovy.json.JsonSlurper
def versionJson = new JsonSlurper().parseText(rootProject.file('version.json').text)
ext.parentVersionCode = versionJson.parent.versionCode
ext.childVersionCode = versionJson.child.versionCode
```
子项目 build.gradle 引用：
```groovy
versionCode rootProject.parentVersionCode
```

**教训**：配置集中管理！一个 JSON 文件比三个硬编码值可靠得多。

## 🧠 核心经验总结

### 开发原则
1. **DeviceOwner 优先**：能用 DeviceOwner API 就不要用普通方式（静默安装、禁装策略）
2. **并发 > 顺序**：网络请求一律并发取结果，不要顺序尝试
3. **配置集中**：版本号、API地址等放一个 JSON 文件，代码自动读
4. **覆盖所有场景**：生物识别/密码/首次使用 → 三选一自动路由
5. **XML 必须完整**：任何 View 都不能缺 layout_width/height

### MQTT 坑
1. 重连必须清理旧订阅（否则回调堆叠）
2. 命令必须幂等去重（req_id + TTL）
3. QoS 0 足够用（不要用 QoS 1/2 阻塞）
4. 离线消息会自动消费（cleanSession=false）
5. payload 必须带 HMAC 签名 + req_id + version + timestamp

### 静默安装坑
1. 后台 Service 不能拉起 Activity（Android 10+ 限制）
2. DeviceOwner 的 PackageInstaller.Session 是唯一免弹窗方案
3. 安装后 DeviceOwner 策略会被重置 → 必须重新 enforceAllPolicies

### 调试技巧
1. `adb logcat -d -t 3000 | Select-String "FATAL|AndroidRuntime|Caused by"` → 秒找崩溃
2. `adb shell dumpsys package 包名 | grep versionCode` → 确认安装版本
3. `adb shell dpm list-owners` → 确认 DeviceOwner 状态
4. `adb shell pm list packages -d` → 列出已禁用包
5. 无线ADB：先 pair 再 connect，配对码端口和连接端口不同
